Gradual rollout not built

Activate is a 100% switch. Traffic is never split today. The runtime for splitting it, though, is already on the request path: config_client.resolve() buckets every request by a salted hash of session_id, compares it against rollout_pct, and stamps arm and experiment_tag onto both the response and the stored conversation. What is missing is this control surface and a ramp policy — health thresholds, a step schedule, and an auto-rollback trigger.

Slicing this by experiment not built

GET /api/conversations already accepts ?tag= and ?arm=, and experiment_tag is an indexed column — the query path exists and is what the table above is read through. Three things are not built on top of it:
  • filtering and search by tag, and a baseline-vs-candidate comparison of the two arms
  • promoting a production conversation into datasets/golden.yaml as a new case, which is the honest way to grow a three-case dataset
  • re-running the judge over a tagged slice on a schedule, with a violation-rate threshold — the missing piece is the schedule and the threshold, not the judge, and not the data
